Im Unterschied zu „06 wegesystem A“ prüft jede turtle nur die drei Patches direkt vor sich – schräg links, geradeaus und schräg rechts – und bewegt sich entsprechend: Sie dreht sich um 45° nach links oder rechts oder geht geradeaus, immer einen Schritt weit. Wo sie war, erhöht sie die Markierung mark des Patches um mark-strenght, solange max-mark nicht erreicht ist; in jedem tick verfällt jede Markierung um decrease-per-tick.

Die Richtung wählt die turtle zufällig, gewichtet nach den Markierungen vor ihr: P(links) = (33 + m₀) / (100 + m₀ + m₁ + m₂), entsprechend geradeaus und rechts, mit mᵢ = mark · path-attract. Unmarkierte Richtungen behalten so ein Drittel Grundgewicht; starke Spuren ziehen an. Die Grauwerte zeigen mark von weiß bis schwarz (in der dunklen Darstellung umgekehrt).

So entsteht ein zusammenhängendes Wegesystem, das sich laufend verändert. Mit den Voreinstellungen ergibt sich nach einigen tausend Schritten (Clock) ein relativ orthogonales Hauptwegesystem; veränderte Werte brauchen einige hundert Schritte, um sich einzupendeln. Die Fassung „09 B update 1“ startet alle turtles in der Mitte nach Norden, erlaubt Wege mit der Maus einzuzeichnen und zeigt mit show-mark-over nur Markierungen ab einer bestimmten Stärke – das Raster wirkt als gemeinsamer Speicher, über den die turtles indirekt miteinander kommunizieren.

Die Fassung „06 wegesystem A“ ist das erste Experiment der Reihe: Dort untersucht jede turtle alle acht Nachbarzellen und wählt eine der absoluten Richtungen 0°, 45°, …, 315° mit P(i) = (12,5 + mᵢ) / (100 + Σ m). path-attract bestimmt die Dichte der entstehenden Cluster; weil keine Richtung bevorzugt ist, entstehen Ballungen statt eines orthogonalen Netzes.

Die App ist eine Neuumsetzung von wegesystem02direction.nlogo (sowie wegesystem04.nlogo und wegesystem01.nlogo) von Reinhard König. Was geändert wurde, steht in QUELLE.md.

Unlike “06 path system A”, each turtle checks only the three patches right in front of it – ahead-left, straight ahead and ahead-right – and moves accordingly: it turns 45° left or right or keeps straight, one step at a time. Where it has been, it raises the patch’s mark by mark-strenght as long as max-mark is not reached; every tick each mark decays by decrease-per-tick.

The direction is chosen at random, weighted by the marks ahead: P(left) = (33 + m₀) / (100 + m₀ + m₁ + m₂), likewise straight and right, with mᵢ = mark · path-attract. Unmarked directions keep a base weight of one third; strong trails attract. Grey values show mark from white to black (reversed in dark mode).

A connected path system emerges and keeps changing. With the defaults, a fairly orthogonal main path network appears after a few thousand steps (clock); changed values need a few hundred steps to settle. The version “09 B update 1” starts all turtles in the centre heading north, lets you draw paths with the mouse and uses show-mark-over to show only marks above a given strength – the grid acts as a shared memory through which the turtles communicate indirectly.

The version “06 path system A” is the first experiment of the series: each turtle examines all eight neighbouring cells and picks one of the absolute directions 0°, 45°, …, 315° with P(i) = (12.5 + mᵢ) / (100 + Σ m). path-attract sets the density of the emerging clusters; since no direction is preferred, clusters form instead of an orthogonal network.

The app re-implements wegesystem02direction.nlogo (as well as wegesystem04.nlogo and wegesystem01.nlogo) by Reinhard König. Changes are listed in QUELLE.md.
